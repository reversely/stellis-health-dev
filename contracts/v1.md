# Device API v1: resource shapes

Base URL on the current macOS device: `http://127.0.0.1:8765/api/v1`. JSON is UTF-8. IDs are UUIDs, times are UTC ISO-8601, offsets are integer milliseconds. This file is the cross-client contract; implemented and planned fields are distinguished below.

## Implemented in #11 / versioned in #21

- `GET /health` → `{status, mode, version, api_version}`.
- `GET /conversations` → array of `{id, title, duration_ms, created_at}`.
- `POST /conversations/import` multipart `file` → `{conversation, duplicate}`.
- `GET /conversations/{id}` → conversation summary.
- `GET /conversations/{id}/audio` → original media with byte-range support and `Cache-Control: no-store`.
- Errors: HTTP 400 for invalid media, 404 for unknown ID. A future error envelope will add stable codes before more clients depend on it.

## To implement in #12–#15

- `GET /capabilities` → `{device_id, engines:[{id, kind, model, languages, ready}], features:{record, transcribe, diarize, summarize}}`.
- `POST /conversations/{id}/processing-jobs` → `{id, conversation_id, state, stage, progress, input_digest, pipeline_version, created_at, updated_at, error}`. Idempotent for the same audio digest and pipeline version.
- `GET /jobs/{id}` → same job. A client polls initially; event streaming can be added without changing the resource.
- `GET /conversations/{id}/transcript` → `{conversation_id, revision, language, segments:[{id, start_ms, end_ms, text, words, speaker_cluster_id, provenance, confidence}]}`. Each word has `{id, start_ms, end_ms, text}` when measured.
- `PATCH /conversations/{id}/transcript/segments/{segment_id}` takes `expected_revision` and edited text/word data; returns the new revision or conflict.
- `GET/PATCH /conversations/{id}/speakers` distinguishes acoustic clusters, display names, and confirmed speaker assignments.
- `POST /conversations/{id}/speaker-rematch` preserves confirmed assignments and returns a job.
- `GET/PUT /vocabulary` holds user terms and language so a new processing run can use them where the installed ASR adapter supports hints.
- `POST /conversations/{id}/ai-runs` explicitly sends selected transcript text to Nebius and returns persisted result IDs with source segment IDs and the transcript revision.

## Hosted sync (separate origin and service, #17)

`POST /sync/push`, `GET /sync/pull?cursor=`, and encrypted chunk upload/download accept opaque ciphertext envelopes only. Authentication uses OIDC session/device membership (#16). Hosted sync never implements device-service audio or transcript endpoints. Browser key enrollment/decryption happens client-side.
