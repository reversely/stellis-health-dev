This is a scoped home change. Granola's upcoming calendar cannot be copied into Stellis without a calendar source and consent flow. The video also hides the transcript during note-taking, but Stellis has an explicit transcript replay and correction workflow from the Otter reference. Keep that workflow accessible; decide its default placement with a live comparison of Stellis's recording and conversation screens.

The original audit treated every unfinished recording as an interruption. The local data contained one recoverable session, and [the former 390px home](refs/granola-tutorial/stellis-home-recovery-mobile.png) placed a yellow recovery bar above search. That placement and label conflated a live recording with one left after a tab closed. The later correction below supersedes this part of the home assessment.

## Where to steer next

1. **Recording workspace, open:** Audit the live capture screen against the 2:18–3:20 state. Count simultaneously visible controls, keep writing or Live transcript as the central task, and move extra AI prompts behind the existing chat pane or a compact trigger if the current layout competes with note-taking. Preserve the existing Notes and Live transcript tabs and fixed recorder. Check desktop and 390px before changing it.
2. **Conversation reading, open:** Compare the first viewport of Notes, Transcript, and Edited Transcript with the 3:32 and 5:05 states. The enhanced document should be readable before generation controls or status text claim the most space. Keep source access close to each generated claim. Do not merge My Notes and Enhanced Notes or hide transcript navigation just because the tutorial does.
3. **Copy consistency, implemented, visual verification pending outside home:** The remaining middle-dot UI strings across recording, search, processing, transcript, profile, sign-in, and sync were replaced. A scan of `src/stellis` now finds none, and the changed JavaScript files pass syntax checks. Check those alternate screens in their next workflow review.
4. **Home verification, implemented and checked:** At 1440px and 390px, two conversations were visible in the list, category filtering reduced them to one, **Manage library** opened, and there was no horizontal overflow. Search returned results for a known conversation, Import opened and closed, and Recently Deleted opened with vocabulary hidden. A further pass should exercise a longer library and an empty library when representative data is available.

The applied home change is deliberately smaller than the whole tutorial workflow. It fixes the observed order-of-information error without claiming calendar, sharing, or cross-meeting AI features that the current Stellis backend does not supply.

## Follow-up: rename a saved conversation

**Feedback, implemented and verified 2026-10-16:** A saved conversation needs a rename action. The tutorial shows an editable note title at 6:31, but does not show the save or reload result. The API test also checks blank input, missing conversations, and deleted conversations.

## Follow-up: recording visible on home

**Feedback, implemented and browser verified 2026-10-16:** The user supplied [a home screenshot during recording](refs/recordinginprogress_home.png) and rejected Stellis's yellow “interrupted recording” bar for that state. These checks used a fake microphone and isolated data, so the earlier real-microphone capture evidence remains the source for audio quality and device behavior.

## Follow-up: live words in recording and home

**Feedback, implemented and browser verified 2026-10-16:** The user reported that live transcription appeared neither in the recording window nor on home. These were separate gaps. On localhost, the running service reported `transcribe: false` because its private model directory was empty after the service moved to a clean checkout. The pinned local Whisper and speaker models were installed and checksum verified; the same service then reported transcription and diarization ready. A browser recording already marked unavailable could not retry under the former client logic.

The recording Notes view now shows the latest provisional words in a compact, clickable Live transcript preview, while the primary Live transcript tab remains the full view. The [mobile recording view](refs/live-transcript/stellis-live-peek-mobile.png) and [mobile](refs/live-transcript/stellis-live-home-text-mobile.png) and [desktop](refs/live-transcript/stellis-live-home-text-desktop.png) home captures show the same recognized sentence. Home keeps at most the latest two provisional segments; a second tab reads the latest saved preview without claiming speaker identity. A failed preview request waits eight seconds before retrying so installing the model during a capture does not strand the transcript in an unavailable state.

In an isolated Chrome capture fed the 11-second `tests/fixtures/jfk.wav` speech fixture, local Whisper produced “And so, my fellow Americans, ask not.” The text appeared in the full Live transcript tab, Notes preview, home card, and another tab's card. A forced first-request model error later recovered on retry. Desktop and 390px pages had no JavaScript errors or horizontal overflow. This is provisional text from saved audio chunks, first requested after about five chunks; the final transcript may differ after processing.
