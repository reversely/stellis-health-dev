# ADR 0037: Complete cited summary points

Status: accepted for development (2026-10-16)

## Context

The 57:49 interview's Nemotron summary retained chronological coverage, but five of eleven overview points were exactly 280 characters and several ended mid-phrase. The provider JSON schema capped every item at 280 characters while local validation permitted 1,000. The first point also claimed an interview affiliation and subject that its three cited opening passages did not establish. Valid passage IDs prove only that a citation exists.

## Decision

Allow up to 1,000 characters in the provider item schema, then locally require overview points to be complete punctuated sentences of at most 400 characters. Prompt Nemotron to keep each point to one concrete claim from at most three nearby passages. Limit each overview to four resolved source passages so the UI never hides a source behind a compressed range. For each chunk overview, compare concrete words in its claim with its own cited passage text and displayed speaker names. A point with less than 75% word coverage is returned for one correction that includes the prior cited lines and missing claim terms, asking the model to remove unsupported details or choose closer passages. If a broad point still fails this check, make a focused request using the three adjacent passages with the strongest combined concrete-word content, rewarding windows where all three contribute. The focused request uses a 60% word cue because its evidence is restricted to those three short passages and ordinary paraphrases can change several words. For a focused point of at most 200 characters that ends in a content word, local validation can add a missing final period; dangling conjunctions still fail. Focused points link all three nearby passages, even if the provider names only one, so the context used to write the claim remains inspectable. Generic `Speaker N` references in generated overview text become `a participant`, because one passage can mix voices and provisional numbers are not names. A failed focused response stops the run without publishing a partial result. The browser keeps the previous successful summary visible with a brief label while a replacement runs or fails. Keep the existing bounded chunk extraction, chronological anchor per chunk, and source IDs. Bump the prompt version so new runs can be distinguished from older output.

For a long interview part, a cited overview must also contain at least ten distinct concrete source words. The first completed real run produced a claim about a “chef role” from one garbled 3.9-meter fragment; word overlap alone accepted it, but the surrounding transcript describes a satellite ground station. The thin-source check routes such a claim to correction or focused nearby evidence. In the focused path, all three passages supplied to the model are assigned as citations before validation, so the checked evidence matches the links shown to the user. When adjacent windows tie on concrete content, use the later window to capture the next fragment of an unfinished phrase. [ADR 0039](0039-summary-overlap-tail.md) separately covers an overlapping closing part that cannot support a meaningful point.

Citation IDs, audio seeks, and word overlap are structural cues, not a semantic fact check. The overlap rule can miss a false claim using the same words as a source, and can reject a valid paraphrase. Audit sampled claims against cited transcript and audio during real-interview validation. Do not label the results as verified merely because the guard passes. A later semantic review feature may add explicit claim-level review if real runs still show unsupported claims.

## Tradeoffs

The schema no longer pressures the model to truncate at 280 characters. The completeness or citation cue can cause one additional billed request per failed chunk; a weak citation can trigger one or two more focused requests. A failed run leaves the previous successful summary available. Focused extraction may choose a minor local detail instead of the chunk's central theme. The cue is applied to chunk overviews, not synthesis topics or AI answers. Sentence-final punctuation is a cheap completeness guard, not proof of grammatical completion or factual support. Manual source review remains necessary for acceptance.
