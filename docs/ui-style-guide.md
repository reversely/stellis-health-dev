# Stellis UI style guide

Use this guide for new screens and when revising existing controls. It records the accepted interface decisions; the [contrast workspace experiment](contrast-workspace-experiment.md) keeps the reference observations and revision history. Inspect any new user supplied reference before changing the related screen, and record what the reference shows separately from design inference.

## Visual foundation

| Role | Color | Use |
| --- | --- | --- |
| Dark core | `#27222B` | Home rail edge, recording rail, auth backdrop |
| Light paper | `#F7F5F6` | Default writing canvas and light card surfaces |
| White | `#FFFFFF` | Inputs and the light theme auth card |
| Dark ink | `#2A252F` | Text on paper |
| Muted mauve | `#413A48` | Dark primary controls and the home rail highlight |
| Dark control | `#37303D` | Secondary controls on the rail |
| Teal | `#335C63` | Home rail focal color, waveform, and light theme focus |
| Wine | `#654654` | Recording Stop action |

Use the roles already defined in `src/stellis/static/theme.css` before adding a color. Check text and icon contrast in both themes. The dark core has a red undertone and is never pure black. Keep the light document surface flat. Dark mode uses a flat mauve document surface.

The **desktop home left rail** is a WebGL fill (`static/rail-shader.js`) of five soft blobs in the user's palette `#495575`, `#56465C`, `#594F4F`, `#547980`, and `#45ADA8` over the dark core. The bright teal blob is smaller than the others. The blobs drift slowly, travel about a quarter of the rail, and lean only slightly toward the pointer. `--rail-blur` on `#rail-shader` sets edge softness from 0 to 1; the default is 0.55 so neighbouring colours blend. Static grain sits in the shader and in an SVG overlay at 30% opacity with an overlay blend. Reduced-motion preferences get one still frame. Without WebGL the rail falls back to the centered radial gradient. Its transparent header is continuous with the rail, with no separate top bar or divider. The recording rail, buttons, cards, notebook, and auth screen use solid fills. Do not spread the gradient across controls or other pages.

## Type and shape

- The brand is the v2 mark (`static/logo-mark.png`, an alpha mask drawn in `currentColor`) beside the lowercase wordmark in upright Piazzolla, in one colour: near-white on dark surfaces, ink on light ones. Never set the logo in italics.
- Use upright Piazzolla 300 (light), approved by the owner on 2026-10-20, for page headings. Keep the existing regular 400 wordmark; use Inter for controls, labels, and body text. Keep a clear size and weight difference between page title, section title, and supporting text.
- Reserve interface italics for long subhead phrases, never headings or isolated label words. User-authored rich text and the Italic formatting control remain available. Recording titles use the same approved Piazzolla 300 face at every viewport.
- Do not place an eyebrow or overline above a heading. Avoid decorative taglines and explanations that do not help someone act.
- The conversation document is square and attaches cleanly to its notebook tabs. Primary tabs (Notes, Transcript, and the recording page tabs) have a 7px top radius and square bottom corners; the large outward curves are retired. An unselected tab is a quiet raised surface with muted text and a hairline border. The selected tab is inverted (text-colour fill, surface-colour label) and sits on the 2px rule that joins it to the document. `.view-tabs` is the same shape for notebook view tabs. Keep My Notes and Enhanced Notes quieter than the primary tabs.
- **List widgets** (`.list-widget`) are a heading row (`.list-widget-head`) over plain rows (`.list-widget-rows`, `.list-widget-row`) on the page surface. There is no white card box and no fill. A hairline separates one row from the next and appears nowhere else.
- **Dates in lists are plain text, never pills.** Pills are for tags and categories. `formatListDate(isoDate)` in `shared/list-date.js` returns Today, Tomorrow, a weekday within the next six days, or a short date such as "Oct 24" (with the year when it is not the current one). Put the result in a `.list-widget-date` element at the right of the row. The Date format setting in Account settings (Relative, Short date, ISO) is stored per browser in localStorage under `stellis-date-format`, and the formatter reads it.
- **To-do lines in notes** show a date typed in the line ("tomorrow at 3pm") as plain right-aligned text drawn by `formatListDate`, never a pill. A canceled to-do is struck through with a dash in its box. A ⋯ button at the right of the line opens Complete, Cancel, and Reopen; ⌘D completes and ⌘⇧D cancels, and typing `[-] ` at the start of a line cancels it.
- Use small corners for cards and controls: roughly 6px for cards and 8px for ordinary inputs and buttons. Do not apply a large radius to every surface.

## Controls and states

- Style every interactive element explicitly. A primary button has a filled surface, clear text, at least a 44px touch target, and a visible hover, keyboard focus, and disabled state. The auth submit button is 48px tall. A secondary button is visibly quieter but still reads as a control. Never leave a browser default button in a finished screen.
- An **inverted** control fills with the theme's text colour and draws its glyph in the colour of the surface behind it, in both themes; it is not a flat accent fill. Summary regenerate is a 44px inverted icon button with no text button beside it.
- The theme switch is a bare 44px sun or moon icon in the header with no border, fill, or text. Take new UI icons from Tabler Icons (MIT, outline, 2px stroke) and record each in `static/icons.NOTICES.txt`.
- Keep Record, Import, Pause, and Stop visually related within the solid recording rail. Use the wine fill for Stop. Do not give Record a competing bright accent.
- Label inputs directly. Use a semantic `button` with an explicit type when it sits in a form. Icon-only buttons need an accessible name. Errors appear close to the action and describe what the user can do next.
- Show live recording and transcription where the user is working; make interruption and recovery states explicit. Match the status text to the actual recording state.
- **Inference configuration:** Read `ai.configured` from `/api/v1/capabilities` when showing AI actions. Explicit local mode needs no Nebius key; it uses the GN100 runtime and loopback inference endpoint. Cloud mode uses its own credentials and configured gateway. Settings names the profile, distinguishes configured routes from live checks, and offers installed local model switching only to the runtime owner. Saved results remain readable when inference is unavailable. Do not present cloud-key setup as a requirement for local inference.
- **Agent avatars:** `shared/agent-avatar.js` draws every agent's avatar from its ID: a 7 by 7 pixel sprite mirrored about its middle column, in one of eight palette colours. Coordinators (the default agent and notebook stewards) show a white sprite on a filled disc; acting agents show a coloured sprite on a white disc with a hairline ring. The same module serves the Chat list and thread, suggestion cards and the recording AI Chat panel. The avatar is decorative (`aria-hidden`) because the agent name always sits beside it.
- Use short, familiar UI labels. Do not use interpuncts or middle dots (`·`) anywhere in user-facing copy, including metadata. Never mention Otter in the product UI. Show an unnamed speaker as `Speaker N` with no appended prompt.

## Screen hierarchy

- **Home:** The left rail is the file structure. At its head are the pinned entries **Meetings** (microphone; the Home list), **To-dos** (check circle; opens `/todos`, the full To-dos page), and **Chat** (people; opens `/chat`, the named-agent workspace). Under the **Library** title come collections (folder icon, count of notebooks), each expanding to its notebooks (colour dot, count of items) that expand to their meetings (microphone) and notes (file icon) newest first by capture or edit time; then a **Notebooks** group for notebooks without a collection, then **No notebook** (inbox icon). A chevron toggles every branch; collections and groups start open, notebooks start closed, and the choice is remembered per browser, while an active tag filter shows every match open. A notebook name opens its page; a collection name toggles it, since collections have no page yet. **New collection** (folder-plus) at the foot opens an inline name field; Enter creates, Escape cancels. Rows keep their full titles and the short date leading the first Summary topic. Selecting a note opens it at `/page/<id>`; notes also drag and move; **Account settings** is pinned at its foot as a light glass button with a gear. Tag pills under the rail title filter the list: select several to show conversations carrying any of them, Untagged shows those with none, and Clear resets. Each rail row shows the full title, then the short date leading the first Summary topic. Titles, topics, meeting names, and progress points on Home wrap in full; they never end in an ellipsis. The main column starts with a heading row: **Home** with a ⋯ menu at its right (Edit widgets, Custom vocabulary, Tags, People, Recently deleted, Take the tour (bulb icon), each with an icon). **Edit widgets** opens a dialog that shows or hides each Home widget, kept per browser. Under it sits the action row: a rounded search field, the inverted **New note** button (note icon; it creates an untitled note and opens it) and the inverted **Record** button (microphone) joined to a chevron menu that holds **Import recording**. Below, at a main width of 720px or more, two columns sit side by side; narrower, they stack with the left column first. The left column is the **To-dos** widget. The right column holds, in order, **Coming up** when a calendar is connected, **Notebooks**, **Recent conversations**, and **Tags** with a + that opens the Tags dialog; every widget heading carries an icon. Notebooks are grouped under their collection (folder icon, the collection name), then notebooks outside any collection; a dashed **No notebook** strip follows and takes a dropped meeting or note out of its notebook. **Recent conversations** is a list widget of the ten newest meetings with a show-more button, the same tag pills as the sidebar (one shared selection), and a plain right-aligned date from `formatListDate`; its rows drag onto notebook and tag cards. Tag cards are neutral and compact, most used first: the tag name (which filters the rail to that tag), a count, and its five newest conversations; an empty tag invites a drag. Notebook colours belong to notebooks only. Coming up is a plain list of the next five meetings that have not ended, however far ahead, one row each with the day and time (Today, Tomorrow, a weekday within the week, then a short date), the full title, a notes button drawn as paper with a folded corner (lined once the meeting has notes), and a small ring-and-dot record button. A list and calendar toggle sits at the heading's right and is remembered per browser; the calendar shows Today, Tomorrow, and the third day as hour-grid columns with all-day events above, overlapping meetings side by side, and a bar with a dot at the current time in today's column. The notes button opens the meeting's notes in a dialog with Record and Done. A notebook card fills with its own palette colour and shows a notebook icon, the name, a + button, its newest item (meeting or note, each with its own icon), up to three progress points with check icons, and up to three older items; every item drags out to another card, a tag, or No notebook. Keep the cards visual and short: icons, colour, and space carry the structure rather than labels. At narrow widths the main column comes first and the sidebar follows on a solid dark band. In both layouts the file tree scrolls inside its own region: at desktop width it fills the space between the Library heading and the pinned foot (with a 140px minimum, below which the rail itself scrolls), and on the narrow band it stops at 60% of the window height. A live recording keeps its card with a clear live state and current text when available. A sidebar meeting or note drags onto a notebook (a move) or onto No notebook (removal), a sidebar notebook drags onto a collection or onto the Notebooks group (out of its collection), and a meeting also drags onto a tag card to add that tag or onto a Home notebook card; a conversation has many tags and one notebook. The branch under the pointer takes a solid outline in the text colour, and a status line names the result. Every row has a **Move to…** button (arrows-move icon, shown on hover or focus on desktop and always on touch) that opens one dialog listing the destinations, so keyboard and touch users never need to drag. The conversation menu keeps Move to notebook.
- **Home agents:** The Agents widget leads Home, above the columns. It groups agents like the notebooks: each collection, then **Notebooks** for notebooks outside one, then **No notebook**. An agent with notebooks in several collections appears under each. Coordinators lead each group. A chip is a 44px pill with a 36px agent avatar, the name, the notebook names in that group, and a **Steward** tag when it stewards one of them; it links to `/chat/{id}`. Edit widgets can hide it, and the choice persists per browser.
- **Agent settings:** A view in Chat at `/chat/settings`, reached from **Agent settings** beside **New agent** and from **Settings** in an agent's thread; not from the rail or Account settings. It groups agents the same way as Home (`shared/agent-groups.js`). Each agent is a closed row (avatar, name, role, notebook names, **Steward** tag) that opens to its name, role and instructions, its notebooks and steward choice, and its memory, with **Open chat**. The per-agent Setup tab exposes that agent's editable instructions, assignments and memory; the global management view remains separate.
- **To-dos:** One component (`static/todos-widget.js`) serves Home's left column, the pinned To-dos page at full width, and a notebook page (scope: all notebooks, grouped under a notebook header, or one notebook, flat). A heading row carries the Open, Completed, and Canceled filters (icon buttons with small corners, the selected one inverted), then an input row that adds a to-do to the uncategorized note titled "To-dos" (created on first use; on a notebook, that notebook's own note), then plain rows with no card boxes. A row is a checkbox (toggles Open and Completed, and reopens a canceled item), the text, a thin grey source label that links to the meeting, and a right-aligned plain date: the due date for an open item, the completed date for Completed, the canceled date for Canceled. A pending agent suggestion shows as a quiet sparkles label (a link to the source note or meeting, where its card waits) on a faintly tinted row with a straight 2px left edge. The list runs to the end with no truncation; an empty filter shows one line.
- **Suggestions:** Agent suggestions (`static/suggestions.js`) render around the notes editor, never inside its document, in a meeting's My Notes and on a note page. Agents never insert blocks into the notes. When pending suggestions exist, a 300px column of cards stands beside the editor and stacks under it below 900px. The column head holds the count, previous and next (chevron-up, chevron-down; each scrolls to and focuses a card), **Accept all** (double-check icon) and **Reject all** (X icon). A card has a straight edge (border-radius 0), a 24px agent avatar with the agent name ("Transcript Agent", no tag text), the change in words (**Add to-do:**, **Mark done:**, **Cancel:**, **Reopen:** and the line's text), the evidence quote with a clock-icon link that seeks the transcript, and accept (check) and reject (X) icon buttons, all 44px with accessible names. An evidence segment that does not resolve (sample meetings are not transcribed) shows the quote and the link reads "Open transcript", which opens the transcript at its top without an error. Pending `add_todo` suggestions also show as green lines under a "Suggested to-dos" label below the editor, each editable in place (`PATCH /suggestions/{id}` on a pause or blur) before it is accepted. A pending `set_todo_status` suggestion tints the matching to-do line in the editor, found by its text, without changing the document. After an accept the notes are read again so the server's lines and IDs appear. A queued or running Transcript Agent run shows "Transcript Agent is reading this meeting" above the editor; other states show nothing.
- **Workspace setup:** Home’s **Set up workspace** and **Take the tour** open the real welcome → uses → review flow. There is no spotlight overlay or browser-local tour resume. Eight use choices have selected checkmarks and contextual Chief of Staff guidance. Review uses the shader library rail, collection/notebook cards, source review and selectable template agents. Choices survive reload and Back through account-scoped server state. Completing a reopened setup adds reviewed notebooks and deployments without removing existing workspace data. Local inference is explicit; cloud configuration remains separate. Show a connect action when sources are disconnected, actual reading progress while active, and reviewable evidence when ready. Never use illustrative source counts or claim a model is ready before a live check.
- **Notes:** A note (the UI never says "page") opens at `/page/<id>` from the sidebar, a notebook card, search, or New note on Home. Under the back link, a title row carries the file icon, an editable serif title (saved on Enter or blur) and a trash button that moves the note to Recently deleted after a confirmation. Below, one row holds a notebook select (notebook icon, with No notebook) and a tag pill for every tag (tag icon, small 4px corners; a selected pill is inverted), each saving at once. The formatting toolbar and the shared notes editor follow, with the save status beneath. Typing `/` on an empty line or after a space opens the slash menu (`static/notes-slash.js`) in every notes editor: a 320px card at the caret (flipped above near the bottom edge, at most the viewport width less 16px) with sections Basic blocks, Layout and Media, a Tabler icon and the Markdown shortcut at the right of each row, filtering as you type, arrow keys and Enter to insert, and Escape to close and keep the typed slash; Image appears only where the editor can upload images. The editor saves one PUT per edit with the expected revision, keeps a local draft, merges on conflict, adopts server-assigned to-do IDs, and sends typed dates as `todo_dates`. Images paste or upload into the note; an image pasted from another note, meeting, or recording is copied so the note owns it. The body is one column up to 820px and fits a phone with no horizontal scroll.
- **Account settings and notebook pages:** Settings groups Profile, Sign-in, Custom vocabulary, Date format, Integrations, and Delete account, each under an icon tile. Primary actions are inverted buttons; Delete account uses the wine fill. The notebook page is documented in its own bullet below.
- **Notebook page:** `/notebook/<id>`. Under the back link, a header band tinted with the notebook colour at 24% opacity over the page (so it does not clash with the dark sidebar or the light page) holds a breadcrumb, `collection / notebook`, with a folder icon on the collection (plain text, as collections have no page) and the notebook icon and serif name as the last crumb. At its right: the inverted **New note** (note icon; creates a note in this notebook and opens `/page/<id>`) and **Record** (microphone; records into this notebook) buttons and a ⋯ menu with **Add a conversation** (plus), **Settings** (gear), **Export Markdown** (markdown icon), **Export for Stellis** (file-zip icon) and **Delete** (trash). Both exports call `GET /api/v1/export?scope=notebook&id=<id>&format=markdown|stellis` and download the ZIP. Below sit the `.view-tabs` **Overview** (dashboard icon) and **List** (list icon). Overview holds the To-dos widget scoped to this notebook (its input appends to this notebook's "To-dos" note) beside **Latest summary** (sparkles; the Summary overview of the newest meeting that has one, shown unmodified under a link to that meeting; the section is omitted when no meeting has a summary), then **Notes and meetings**. List shows only the items table. The items table has columns for an icon (microphone for a meeting, file for a note), the title, a plain right-aligned date from `formatListDate`, tags as pills (the only pills on the page), and to-do counts (open circle and completed check-circle, each with a number). The All, Meetings, and Notes filters are small-corner icon buttons, not pills. No status labels are invented. Under 640px each row becomes a grid: icon, title and date on the first line, tags and counts on the second. **Settings** opens a dialog with the name, the colour (the twelve presets from `GET /notebooks` as swatches, plus a custom field that takes `#RRGGBB` and a native colour picker), the collection, and **Suggest to-dos from meetings**: `Like <collection>` (or `Off` when the notebook has no collection), `On`, `Off`, saved with `PATCH /notebooks/{id}` `todo_list`. Card text on a notebook colour uses whichever house ink has the higher contrast, so custom colours stay legible. The **+** on a Home notebook card opens a dialog with **New note**, **Record**, and **Import**, then the list of conversations to move in.
- **Recording:** Keep capture actions and status in the dark rail; give the light notebook or transcript the wider reading area. Notes and Live transcript are the primary tabs.
- **Coming up notebook:** Each event has a Notebook action beside Notes and Record. Its dialog chooses a notebook or No notebook, with Apply to this series for recurring events. The chosen notebook name appears under the meeting title and Record carries that notebook into the recording.
- **Saved conversation:** Attach the primary file tabs to the square document. Keep transcript reading, seeking, notes, and related actions in predictable positions.
- **Authentication:** Use a centered paper card on the dark mauve backdrop. Make Sign in and Sign up clear, give the submit button the same deliberate shape and states as other primary actions, and support the light theme.

## Before merging a UI change

1. Inspect each named reference and relevant existing screen state. Recheck earlier feedback for the same workflow in [the reference ledger](otter-ui-reference.md) and [the contrast experiment](contrast-workspace-experiment.md).
2. Compare the rendered result in a browser at desktop and narrow widths, in both themes where available. Check the relevant default, hover, focus, disabled, loading, error, and alternate states. Check for horizontal overflow and page errors.
3. Verify behavior as well as appearance: tab changes, live updates, status transitions, and form submission where touched. Record observed results separately from inference and update this guide if an accepted design decision changes.

## First-run setup

The first-run screens follow PDF pages 7–9 by workflow, while retaining the shipped fonts, logo, Tabler icons, generated agent avatars and the rich sidebar shader. Welcome and uses have no library rail; reviewed proposals introduce it. Tablet and phone layouts move the surrounding welcome icons into a stable grid. Scene changes use a 220ms opacity/8px transform transition, disabled by reduced motion; there is no continuous decorative icon motion.

Local setup explicitly says Completely local inference and names GN100. Cloud setup names Nebius Cloud + Token Factory separately. Readiness requires a live check, and errors use the server response. Starter notebooks are labelled as based on choices; illustrative wireframe counts and schedules are never presented as real data. Use tiles expose pressed state and retain stable accessible names. Existing accounts bypass first-run setup.

- **Agent conversation workspace:** Chat reuses the full shader library rail, with agent identities above the collection tree. The active agent has Thread / Setup / Work tabs, Call beside its identity, a separately scrolling conversation and a persistent bottom composer. Notebook chips belong to individual messages; the composer scope uses a familiar select. Unsent text and selected scope survive agent switches and reload within the current browser session, keyed by account and agent. Submission appears immediately; real job state is polled without implying token streaming, and the next unsent draft is not replaced when a reply arrives. Control/Command+Enter submits. The context panel displays real output behavior, assignments, memory and named copies. Existing draft/delegation tools live in Work. On phones the agent picker is at the top and the library follows the conversation. The broader reviewable-artifact workflow remains tracked in #437; notebook-row agent management remains #438.
